# 资料库

自己的本地素材库。**不是扫描器**——素材是复制进库里的，归你管、可分类、可编辑。资料库下可以并排放多个**库**，每个库结构完全一样、互相独立。

素材源（`E:\X-Vault珍藏馆`）只是取料的地方，源文件始终保持不动。

当前版本 **v3.42**（2026-10-27），57 个 tag，e2e 140/140。

## 快速开始

双击 `start.bat` → 浏览器打开 `http://127.0.0.1:7788`

或者双击 **`资料库.exe`**：不用开命令行、不用浏览器，窗口里就是同一个页面。

### 桌面壳（单文件 exe）

`资料库.exe` 是一个 700 KB 左右的原生小壳（Rust + WebView2），只做三件事：把本机 Node 服务拉起来、
用 WebView2 打开 `http://127.0.0.1:7788`、让 F5 / Ctrl+R 能刷新。
**页面还是 `web/` 里那一套，一行 HTML 都没改。**

| 行为 | 说明 |
|---|---|
| 单文件 | 静态链接 CRT，不依赖任何 dll；只需要系统自带的 WebView2 Runtime（Win10 1803+ / Win11 自带） |
| 找 Node | `AMS_NODE` → `PATH` → `Program Files\nodejs` → WorkBuddy 内置目录；都找不到时显示一张说明页 |
| 复用服务 | 端口上已经有健康的服务就直接连（比如你之前用 start.bat 起的），不抢端口 |
| 关窗即停 | 服务是它起的，关窗口会一起结束；复用别人的则不动 |
| 端口冲突 | 明确提示「端口被别的程序占了」，可用 `AMS_PORT` 换端口 |
| 刷新 | F5 / Ctrl+R（注入脚本在捕获阶段拦，不影响页面自己的键盘逻辑）；WebView2 默认右键菜单里也有「重新加载」 |
| 日志 | `%LOCALAPPDATA%\ams-desktop\shell.log`（壳）、`server.log`（Node 输出） |

改了壳代码才需要重新构建：

```bash
node desktop/build.mjs      # cargo build --release + 拷成项目根的「资料库.exe」
```

需要 Rust 工具链 + VS2022 Build Tools（本机已装）。**exe 必须待在项目根**——它从自己所在位置
向上找 `server/src/index.js`；要放桌面就建个快捷方式，别把 exe 单独拷走。

## 层级

```
资料库（我的资料库）
 ├ 人物库   ← 放真人
 │  └ 人物（名字 / 简介 / 标签 / 平台账号）
 │     └ 图包（按月份，也可手动新建）
 │        └ 图片 / 视频
 ├ 角色库   ← 放虚拟角色
 │  └ 角色（名字 / 简介 / 标签 / 出处）
 │     └ 小库（官图 / cosplay / 同人）
 │        └ 图包（按月份）
 │           └ 图片 / 视频
 ├ 散图库   ← 放散图 / 杂图（扁平库，只有图包和全部素材）
 │  ├ 图包（按月份或自定名字，封面 = 前 9 张拼图）
 │  │  └ 图片 / 视频
 │  └ 全部素材（含全部图包）
 ├ 表情库   ← 放表情包（扁平库，没有条目层）
 │  ├ 图包（自定名字，封面 = 前 9 张拼图）
 │  │  └ 图片 / 视频
 │  ├ 未分类（没归包的）
 │  └ 全部素材（含全部图包）
 ├ 资源库   ← 游戏 / 动画 / 电影 / 剧集（扁平库）
 │  └ 资源（原神…）── 靠「同名标签」串起人物库 / 角色库里的条目
 ├ 小说库   ← 原创库 / 同人库（一本书一个条目）
 │  └ 小说（书名 / 类型或原作 / 作者 / 字数 / 简介）
 │     └ 未分类 / 文件
 └ 全部库   ← 收件箱 + 全库总览（不复制文件）
    ├ 未分发   ← 落在 全部库/未分类/图片|视频 里的
    └ 已分发   ← 全库其余所有图片 / 视频的只读聚合
```

所有库的层级都是「库 → 条目 → 图包 → 图片/视频」，**区别主要在条目上那一栏**
（散图库 / 表情库 / 资源库 / 全部库是扁平库，没有条目层）：

| 库类型 | 那一栏 | 填什么 | 点一下 |
|---|---|---|---|
| 人物库 · 真人 | **平台** | 平台 + ID（主页网址选填） | 有网址就跳转，没有就复制 ID |
| 散图库 · 扁平库 | 没有这一层 | — | — |
| 表情库 · 扁平库 | 没有这一层 | — | — |
| 资源库 · 扁平库 | 没有这一层 | 分类（游戏 / 动画 / 电影 / 剧集） | — |
| 全部库 · 扁平库 | 没有这一层 | — | — |
| 角色库 · 虚拟 | **出处** | 类型 + 作品名（链接选填） | 有链接就跳转，没有就复制作品名 |
| 小说库 · 原创 | **类型** | 玄幻 / 仙侠 / 都市…（也是磁盘文件夹） | — |
| 小说库 · 同人 | **原作** | 原作品名（磁盘文件夹 + 自动打进标签） | 「作品页 ↗」跳资源详情 |

出处类型预设：游戏 / 动画 / 漫画 / 小说 / 电影 / 剧集 / 特摄 / 舞台剧 / 同人 / 原创（也可自己输）。

**图包排序**：图包视图工具栏里是一个维度下拉 + 升降序箭头（时间 ↓ = 新的在前、素材最多在前）。
四个维度：名称 / 时间 / 素材数量 / 占用空间；主键相同时按名称升序兜底，所以同月建的包也不会乱序。
排序只在本地重排（不重新请求），并且跨条目记着上次选的维度。

**图包内的媒体排序**：点进图包后，工具栏「N 项」右边是同一套控件（同样一个下拉 + 箭头）。
维度换成名称 / 时间 / 大小 / 类型 —— 类型是图片在前、视频在后，切倒序就是视频在前，几百张里挑视频不用翻。
时间优先取文件名里的日期，取不到才用入库时间（批量导入的入库时间几乎相同，只按它排等于没排）；
默认名称升序。只影响显示顺序，不写库、不动 `media.sort_order`。
媒体详情页的 ← → 序列跟着这个顺序走，按「大小」排完点开第一张，翻下一张还是按大小。

**小库（只有角色库有）**：每个角色下面分三个小库——`官图` / `cosplay` / `同人`，
每个小库内部再按月分图包。角色页图包区上方是三个切换标签，带各自图包数；
上传和「＋ 图包」都会落到当前选中的小库，磁盘路径是
`角色库/<角色>/<小库>/<图包>/图片|视频`。

**散图库（扁平库）**：随手存的散图 / 杂图专用，没有条目层级，只有**图包 / 全部素材**两栏 ——
不设「未分类」分区（上传时没指定图包就按文件名月份归包，没有日期归到当月），
也没有表情库那套「动图 / 表情」筛选。

**表情库**：没有条目层级，库里直接是「图包 / 未分类 / 全部素材」三个分区。
图包封面用包内**前 9 张图拼成 3×3**（不足 9 张按 2×2 / 单张排，空格用浅灰补齐）。
磁盘路径比别的库少一层：`表情库/<图包>/图片|视频`，没归包的落在 `表情库/未分类/图片`。
从首页点「表情库」标签，内容就在原地展开（和人物库 / 角色库一样），URL 仍停在 `/s/:id`。
**表情库 / 资源库 / 小说库 / 全部库这四类都不跳页**，只换内容不换页。

**资源库（第四个库）**：卡片就是「游戏 / 动画 / 电影 / 剧集」这些作品本身。
建一张卡片（比如「原神」），再去人物库 / 角色库给条目打上「原神」标签（或把出处写成「原神」），
它们就会自动出现在原神详情页下方。**不需要维护关联表，标签就是关系。**

- 点关联卡片 → `/c/:id?res=原神`，角色页只显示带这个标签的图包，顶部有一条「来自资源」的提示，可一键显示全部
- 在条目的出处上点「原神」→ 直接跳到资源详情页；返回按历史逐层退回

**标签自己也有落地页 `/tag/:name`**：条目页的标签、图包页标题旁的标签、媒体详情页的标签，
点一下都进这里，三段分别是「条目 / 图包 / 素材」（素材最多列最近 200 个，总数照实写）。
标签的来源只认三处：**条目名**（条目自带）、**图包标签**（名字拆出来的 + 所属条目名）、
**图片自己打的标签**；「人物 / 角色 / 小说」这种库身份不算标签，不会出现在图里。
编辑标签时已选中的排在最前面，粘一整串 `角色-服装` 回车会自动拆成两条。

**小说库（第五个库）**：一本书一个条目，两个变体——**原创库**（按小说类型归类）与
**同人库**（按原作品名归类）。关键点是**两层互不干扰**：

| 层 | 是什么 | 落磁盘吗 |
|---|---|---|
| 分类视图 | 原创库「全部 / 出版 / 网络」、同人库「全部 / 短篇 / 长篇」 | 否，只是筛选（`novel_subtype`） |
| 归类文件夹 | 原创=小说类型（玄幻 / 仙侠…）、同人=原作品名 | 是，目录的一层（`novel_group`） |

- 出版 / 网络、短篇 / 长篇都是**一本书的单一属性**，做成目录会把同类型的书劈成两半，所以只做筛选
- 磁盘是三层：`小说库/<类型或原作>/<书名>/未分类/文件`（没视频层，小说不放视频）
- 类型 / 原作**可以改名**，改名会同步移动磁盘目录并重写库内所有媒体的 `rel_path`
- 详情页那一栏（原创=类型 / 同人=原作）是归类文件夹的只读投影；同人若能对上资源库的作品，
  点一下直接进那部作品的资源页，点其它地方进编辑
- 同人库填的「原作品名」会**自动打成标签**，于是资源库里那部作品的「关联条目」+1，点进去就是同人文
- 没有封面时卡片直接用**书名占位**（不借用作品封面）
- 同一库里**书名不许重名**（409），因为书名同时是目录名

**小说袋**：袋子就是这个库里的「类型 / 原作」实体化（`packs.kind='novel'`，挂在库的容器条目下），
一袋多本。首页是袋子网格、点进去看这一袋的书。袋子**只列当前分类视图下有书的**——
「出版」视图里不会冒出全是网络书的袋子，空袋子也不占位（新建后直接进袋子页）。

**正文**：TXT / EPUB / PDF / MD / DOC(X) 传进来是 `media.kind='file'`，落在
`<书>/未分类/文件`，不归任何图包、不进图片瀑布流、也不进素材挑选器。
- TXT：`/read/:id` 站内阅读。编码判 BOM → 严格 UTF-8 → GB18030（老网文多半是 GBK）；
  分章按整行「第X章 / 卷 / Chapter N / 序章 / 楔子 / 番外」，认不出就整本当一章。
  目录抽屉、A− / A+ 字号、位置（第几章 + 章内比例）存 localStorage，← → 切章、Esc 返回。
- EPUB：**这一期只入库 + 下载**，站内不解析（零构建项目里为了它塞解压 + OPF 解析不划算）。
- PDF：交给浏览器自己打开（`/api/media/:id/raw`，带 Range）。

**漫画**：`packs.kind='comic'` + `media.page_no`，页序和图包排序**完全分开**——
把图包按「大小」排一遍，漫画还是第 1、2、3 页。
- 转换：图包卡片右键 / 图包页空白右键，只改 `kind` 和 `page_no`，文件不搬、封面和标签不动，随时能转回去。
  页序按文件名自然序（`1、2、10`，不是 `1、10、2`）；转回图包会清空 `page_no`。
- 包里有视频时先确认「只转图片」，视频留在包里但不参与阅读（`page_no` 为 NULL）。
- 图包页的漫画模式：标题旁「漫画」标、工具条「N 页」+ 阅读、隐藏排序控件、缩略图左上角页码、
  点图从那一页开始读。
- 阅读器 `/cm/:id` 有三种看法，共用一条顶栏胶囊 + 一条底部进度滑块：
  - **滚动**：上下连续；页高按数据库宽高先占位（滚动条长度一开始就对），进视野前 1200px 才加载并预取前后页。
  - **单页**：一屏一页；**适高**整页进屏，**适宽**顶到两边（超出就滚舞台）。
  - **双页**：左右对开，第 1 页单独当封面，之后 (2,3) (4,5)…；换页只换 `src`，不重建节点。
  - **方向**：左→右 / 右→左。右→左时第一页落到右边，方向键、点击区、滑动全部对调（日漫就是这么读的）。
  - 操作：← → / PageUp / PageDown / 空格 / Home / End、`1 2 3` 切模式、`F` 全屏、`Esc` 返回；
    单双页点右侧 35% 翻下一页、左侧 35% 上一页；触屏可左右滑；全屏静止 2.4s 自动淡出控件。
  - **滚轮 / 触控板在单页、双页里就是翻页**（一格一页，双页一对）；适宽时页面比屏幕高，
    先滚完这一页再翻（60px 累积 + 420ms 冷却，触控板惯性不会连翻）。
  - **全屏是整页（`<html>`）进全屏**，不是 `.comic` 自己 —— 元素自己进全屏后文档不再滚动，滚动模式会卡死。
  - **侧栏**：单页 / 双页时两侧若还有 ≥92px 留白，顶栏收起，返回 / 页码 / 竖向进度条挂左边，
    模式 / 方向 / 适应 / 全屏挂右边；留白不够（双页对开、适宽）自动退回顶栏 + 底部滑块。
  - 进度按「第几页」存，三种模式切换 / 退出重进都是同一页；`?p=N` 可直达；偏好存 `cl-comic:prefs`。

**滚动位置的规则**：按路径存在 `sessionStorage`（`cl-scroll:<路径>`），`pagehide` / 滚动时都会更新。

- **F5 重载**：回到原处（你刚才就站在那儿）
- **前进 / 后退**：回到原处（列表 → 详情 → 返回，列表停在哪还停在哪）
- **点链接进来**：一律从顶部开始 —— 不能因为上次在这页滚过，点进来就停在一半

条目页的「图包 / 全部媒体」也是同一条思路：视图记在历史项（`history.state.tab`）里，
所以在「全部媒体」点开一张图、按 ✕ 回来，落回的还是「全部媒体」，位置也在原处。

浏览器的自动恢复被 `history.scrollRestoration = 'manual'` 关掉（它会在文档还没高度的时候就跳，算成 0）。

**页面右上角不再有「账号 / 来源」**：这个字段和「出处 / 平台」重复，已经合并进详情页右栏那一块。
老数据里的账号会一次性并入平台栏（平台名记为「其他」，点进去可以改）。

**出处弹窗**是「出处类型 + 作品名」，两栏**都是下拉 + 可输入**：

- 出处类型：游戏 / 动画 / 漫画 / 小说 / 电影 / 剧集 / 特摄 / 舞台剧 / 同人 / 原创，也能自己打
- 作品名：列出**资源库里已有的资源**，选一个就挂过去；输入新的保存时**自动在资源库建一张卡**，
  分类就取你填的出处类型（新类型会自动多出一个分类标签）

新增库：首页库标签右侧的 **＋**，填名字并选类型。新库在磁盘上会建同名目录
（`D:\CharacterLibrary\<库名>\`），建条目、传文件时自动按五层展开。

## 怎么往里加东西

1. 首页右上角 **＋ 新建人物 / 新建角色**（按钮名跟着当前库变），只填名字和简介 ——
   名字里用**中英文逗号**隔开（`申鹤，雷电将军`）就能一次建多个
2. 进详情页，点 **＋ 上传素材**，或者直接把文件 / 整个文件夹**拖进页面**
3. 上传后按文件名里的日期**自动归到对应月份图包**；没有日期的进「未分类」
4. 也可以点 **＋ 图包** 手动建月份包；图包支持重命名 / 删除（删除只是解除归属，不删媒体）

### 给图包加内容：四个来源

图包卡片上的 **＋**、卡片右键 → **添加素材**、图包页右上角 **＋ 添加素材**，都是同一个菜单：

| 来源 | 范围 |
|---|---|
| 从全部素材添加 | 整个资料库，**含别的条目** |
| 从本角色素材添加 | 只在当前条目里挑 |
| 从未分类素材添加 | 还没归包的那些 |
| 从本地文件上传 | 走上传队列 |

打开的是**素材选择器**：范围还能再切（全部 / 本角色 / 未分类 / 已归包）、按类型筛、
搜文件名或标签、滚到底自动加载下一页、点选多张后一次加入。
已在目标图包里的素材会置灰并排到最后，一打开就是能选的；
选了别的条目的素材会标出来源，底部提示「其中 N 项来自其他条目，会移动过来」。

> 同条目内添加只是改分组，文件不动。
> **跨条目添加会改归属**：文件会搬到目标条目的图包目录里，原条目那边就没了。
> 搬之前先查重，目标条目已有同内容文件就跳过。

### 上传

- 角色页、图包页、上传页都支持**拖拽上传**，拖整个文件夹也行（会递归取里面的文件）
- **压缩包直接拖**：zip / rar / 7z / tar.gz 会自动解压，只把里面的图片 / 视频入库。
  拖到图包页就进这个图包；拖到条目页就按压缩包名新建一个图包（同名包复用）；
  拖到全部库落「未分类」。`__MACOSX`、`Thumbs.db`、readme 这些会被忽略。
- 上传是**一个文件一个请求、并发 3**，所以每个文件有独立的进度和独立的失败原因
- 页面右下角会出现进度胶囊，点开就是 **上传队列页 `/uploads`**：
  总进度（字节 / 速度 / 剩余时间）、每个文件的状态、失败可重试、已完成可清空
- 上传在后台跑，切到别的页面继续浏览不影响；全部传完当前页会自动刷新数据
- 在上传页里拖文件，会先让你选传到哪个条目 / 图包
- **上传只留一份**：文件先落在 `.cache/inbox` 中转，入库（跨盘复制到数据盘）成功后立刻删掉中转那份；
  数据盘里的原件不会被任何清理动作碰。历史上残留的中转文件可以用
  `cd server && npm run sweep-inbox` 统计、`npm run sweep-inbox -- --apply` 清理 ——
  只有「库里已有同 sha 记录且那条记录的文件确实存在」的才会删，其余保留。

### 全部库：收一堆杂图，再分发

从手机导进来一批图、或者随手存的一堆视频，先丢进「全部库」，再决定它们属于谁。

| 分区 | 里面是什么 | 文件在哪 |
|---|---|---|
| 未分发 | 还没归属的素材 | `全部库/未分类/图片\|视频`，拖进页面或点「收素材」都落这里 |
| 已分发 | 全库其余所有图片 / 视频，**只链接、不复制** | 各自角色原来的目录，点开还是 `/i/:id` |

- 上面再分「全部 / 图片 / 视频」；搜索同时匹配文件名、条目名、图包名
- **选取 → 分发到…**：选库 → 选条目 → 选图包（或「＋ 新建图包（按今天）」），
  确认后文件从 `未分类` **移动**到目标角色的图包目录，`character_id` / `pack_id` / `rel_path` 一起改
- 搬移复用跨条目移动那一套：先落 journal 意图 → 搬文件 → 写库，写库失败会把文件搬回去；
  目标条目已有同内容（sha256 相同）的文件就跳过，并在提示里说明
- 「已分发」是只读聚合：全库三千多个素材都能在这里翻，不会为它多存一份文件
- 已分发超过一页时底部是「加载更多」，不是无限滚动 —— 位置确定，返回时不乱跳
- **库总览**：标题下面一排卡片，每个库一张 —— 主数字是「多少个」（人物 / 角色 / 小说 / 作品 / 图包），
  下面一行是媒体数与占用，最底下一条占比条；点卡片直接切到那个库。
  汇总在「库总览」右边：`7 个库 · 1,530 个条目 · 3,807 个媒体 · 4.7 GB`。
- **右键**：素材上是「打开 / 分发到… / 重命名 / 编辑标签 / 打开本地文件夹 / 删除」；
  空白处是「选取素材 / 全选 / 收素材 / 刷新」。
  全部库没有图包，所以「设为图包封面 / 移动到其他图包」不出现；素材本来就在全部库里，「移出库」也不出现。
- **分发弹窗的条目可搜索**：上千个条目不用滚，直接在「条目」框里打名字（只筛选项，值仍然只能选）；
  一次最多画 60 项，其余提示「继续输入缩小范围」。
- **按标签分发**：素材先打上标签（右键「编辑标签」），分发时如果标签名正好是某个条目名，
  弹窗顶部会出现一行「按标签匹配」，点一下就把库和条目拨过去，确认图包即可。
- **记住上次的库**：分发一个到「角色库」之后，下一张打开时默认还是角色库
  （条目仍默认第一个，免得误分给上一个角色）。刷新页面后回到默认的第一个人物库。
- **多选**：右上「选取」、或者直接 `Ctrl + 点击` / `Shift + 点击` 一张就进选取模式；
  进去后 `Ctrl+A` 全选、`Delete` 删除、`Esc` 退出。
  底部操作栏是「全选 / 分发到… / 删除 / 完成」。
- **右键已选中的那几张之一**时，菜单会自动换成批量动作（分发选中的 N 个 / 删除选中的 N 个），
  避免「选了 50 张、右键删除却只删掉一张」。
- **移出库（反向）**：任意条目 / 图包里的素材，右键 →「移出库」、素材详情页的「移出库」按钮、
  或「全部媒体」多选后点「移出库」，都会退回 `全部库 → 未分发`，文件跟着搬；
  全部库里已经有同一份内容（sha256 相同）时不重复存，这条记录直接合并掉并提示

> 这就是「不同角色图库各自独立、图片没法跨库搬运」的入口：先收进来，再一次性分发，
> 不用为了搬一张图先切库、再走「从全部素材添加」。

### 全部媒体的筛选

切到「全部媒体」后，工具栏中间会多出一排筛选：

| 控件 | 作用 |
|---|---|
| 全部 / 图片 / 视频 | 按类型 |
| 标签下拉 | 从当前条目的媒体里汇总标签，按出现次数排（带计数） |
| 图包下拉 | 任意图包，或「未归包」 |
| 小库下拉 | 只有虚拟角色库才有（官图 / cosplay / 同人） |
| 搜索框 | 匹配文件名或标签 |
| 排序 | 最新添加 / 最早添加 / 按名称 / 文件最大 / 文件最小 |

筛选和排序都在前端做，切条件不会重新请求接口。

表情库的「未分类」「全部素材」用同一套控件，只是类型换成 **动图 / 表情**：

| 控件 | 作用 |
|---|---|
| 全部 / 动图 / 表情 | 动图 = gif（或视频），其余算静态表情 |
| 标签下拉 | 候选值跟着当前范围走；图包标签会下发给包内每张图 |
| 图包下拉 | 只有「全部素材」有；含「未分类（未归包）」 |
| 搜索 / 排序 | 同上 |

> **动图 = 真的有多帧**（`media.anim`，按 sharp 的 `pages` 判定），不是看 `.gif` 后缀 ——
> 微信 / QQ 导出的表情里大量 `.gif` 只有一帧，那些算静态表情。

**悬停播放**：动图瓦片上停 420ms 会换成原件播放并放大，移开立即还原；同时只有一个在动。
**视频瓦片不参与**：以前视频的 `anim` 也是 true，被这条路径一起带上了 ——
悬停就把整个 mp4 原件塞进 `<img>` 解码，播不出来还白烧 IO，现在视频只留右上角一枚小三角角标。

### 媒体详情页

在瀑布流里点任意图片或视频，进入 `/i/:id`：

- 左边是大图（视频直接是播放器），顶部一颗「条目 · 图包」胶囊，点 ✕ 或按 `Esc` 回上一页
- 右边是信息面板：分辨率（视频另有时长）、标签、内容介绍、关联条目、
  存储位置（`库 / 条目 / 图包`）、存储大小、存储时间
- **内容介绍**点一下就变输入框，失焦自动保存；留空则显示「与「xxx」相关的图片素材。」
- **标签**里深色的是这张图自己的，点一下移除；浅色的是从条目继承来的
  （条目名、人物 / 角色），点击只会提示你去条目上改，不会误删
- `←` `→` 在同图包内翻页；点图片进全屏灯箱（灯箱开着时键盘归灯箱管）
- **视频打开就自动静音循环播放**（不静音浏览器会拦），要声音点播放器上的音量按钮
- **视频封面**：播放器下面那颗「设为视频封面」把**当前这一帧**存成封面
  （先暂停再点、或播放中直接点都行，存的是点击那一刻的画面）；存完提示「视频封面已更新」。
  设过封面后旁边多出「恢复默认封面」，点了就退回自动首帧（视频开头 10% 处那一帧）。
  封面只影响这一条媒体的缩略图，所以列表瓦片、图包封面、条目封面用它时会一起变
- 缩略图 URL 一律带 `?v=<THUMB_REV>`（`web/js/api.js`，当前 2）：`immutable` 缓存一旦落盘，
  同 URL 换了内容浏览器也不会回源（连 F5 都不问），只能靠换 URL 作废。改缩略图管道时把它 +1
- 底部还能重命名、在资源管理器里定位、删除
- 「打开位置」：图片 / 视频会在资源管理器里**选中那个文件**，
  图包打开的是**图包根目录**（里面就是「图片」「视频」两个文件夹）

### 标签

条目上可以打标签，点标签行右侧的 **+ 标签** 打开弹窗：上方输入框、下方已有标签列表（点击选中/取消）、底部确认。

- **边打字边筛**：下方「已有标签」跟着收窄成名字里含这段字的那几个，计数变成 `（7 / 184）`；已选中的始终留着
- **查重**：输入一个已存在的标签，会直接选中它并提示「已经有 xxx 了」，不会加出第二个
- **相似校验**：和已有标签很像（包含关系、二元组相似度 ≥ 0.5）时先拦一下，提示「和 xxx 很像，避免重复？」，确实要加可以点「仍然添加」
- 标签是全库共用的，跨库、跨条目复用

**标签点一下是「进对应的库」，不是删除** —— 有同名资源的标签（比如「原神」）点进去直接到资源详情，
没有同名资源的会提示一句；**删除标签改到右键**（右键那颗标签 → 删除标签）。
条目自己的名字标签没有「删除」项，改名时自动更新。

**每个条目自带自己的名字标签**（纸悦 → 「纸悦」），新建和改名时自动同步，条目上那颗不能删。
它也会出现在该条目所有图片 / 视频上。

**媒体自动继承的标签只有两项**：

```
图片的标签 = 图片自己的标签 + 条目名本身 + 库标签（人物 / 角色）
```

条目上手打的通用标签（「原神」「米哈游」这种）**不会**下发到它名下的所有图片 ——
一个人物往往只有一两个图包跟某个作品有关，全量下发会把上千张图一起染色。
要标某一批图：给**图包**打标签（资源页按标签筛图包也用这个），或者给单张图标。

比如纸悦的一张图，标签是 `cosplay / 写真 / 纸悦 / 人物`。灯箱右上角能看到。

### 设为封面

图片右键里有两项**互不影响**的封面操作：

| 菜单项 | 什么时候出现 | 点了做什么 |
|---|---|---|
| 设为图包封面 | 这张图**当前归属某个图包**时；没归包就**隐藏**（置灰只会留个永远点不动的项） | 写 `packs.cover_media_id`，图包卡片 / 表情库九宫格第一格立刻换成它 |
| 设为人物 / 角色 / 资源封面 | 图片归属的条目不是容器（表情库隐藏）；文案跟着库类型变 | 写 `characters.cover_media_id`，条目页左上角封面 + 首页卡片立刻刷新 |

### 批量选择

角色页和图包页的工具栏都有 **选取**，进去之后点卡片 / 瓦片就是勾选（不会跳转），
底部会浮出一条操作栏：

| 在哪 | 能做什么 |
|---|---|
| 角色页 · 图包视图 | 全选 · **解散** · **删除** · 完成 |
| 角色页 · 全部媒体 | 全选 · **移动到图包** · **删除** · 完成 |
| 图包页 | 全选 · **移动到别的图包** · **删除** · 完成 |

勾选圈在左上角，选中带黑描边；点「完成」或切视图退出。
移动只改所属图包（磁盘文件不动），而且**只能移到同一个条目下的图包** —— 跨条目要搬文件，那走「添加素材」。
目标下拉的第一项是 **＋ 新建图包…**，可以直接建一个新包把这些媒体装进去。

瀑布流的瓦片**列宽固定 120px**，高度按每张图自己的比例走（图包页和「全部媒体」一样）。

**解散 vs 删除**（图包）：

- **解散**：只删图包这个壳，里面的媒体变成「未归包」，文件一个都不动
- **删除**：图包连同里面的媒体、磁盘文件一起删掉，不可恢复（会二次确认）

**重命名图片**只改库里的显示名，磁盘文件名保持不动——磁盘名前面那段是内容 sha256，去重靠它。

### 别名栏

详情页 hero 区里，出处栏右边、简介左边那一栏，放**简称、原名、日文名、英文名**。

- 整栏可点（标题、＋、任意标签、空白处都行）→ 弹窗里一行一个，也能直接用逗号隔开
- 最多 20 条、每条 60 字；超出宽度用省略号，鼠标悬停看全名
- 人物库、角色库、资源库（游戏 / 动画 / 电影 / 剧集）、小说库同一套；`characters.aliases` 存 JSON 数组
- **搜索也搜别名**：`GET /api/shelves/:id/characters?q=` 会把 `aliases` 一起 LIKE
- 「编辑资料 / 编辑资源」弹窗里也有这个字段（用顿号隔开），两条路径同一套清洗规则

### 平台账号栏（人物库）/ 出处栏（角色库）

详情页 hero 区中间那栏，内容跟着库类型变：

| | 人物库（真人） | 角色库（虚拟） |
|---|---|---|
| 栏目标题 | 平台 | 出处 |
| 上排 | 平台（下拉可选可输）+ ID | 出处类型 + 作品名 |
| 下排 | 主页网址（选填） | 作品链接（选填） |
| 点卡片 | 有网址跳转，否则复制 ID | 有链接跳转，否则复制作品名 |

共同行为：

- **＋** 添加，悬停卡片出现 ✎ 编辑 / ✕ 删除
- **超过 4 条不再把整栏拉高**：容器内无滚动条滚动，底部渐隐阴影提示还有内容，滚到底阴影自动消失
- 第一列固定 50px，**第二列左边缘严格对齐**，超长省略 + 悬停显示全名

链接只接受 http/https，写 `x.com/xxx` 会自动补成 `https://x.com/xxx`（前后端各补一次）。

## 备份

整个库就是一个目录，**备份 = 复制 `D:\CharacterLibrary`**。`.cache` 不用备份——删了会自动重建。

一键备份（双击 `backup.bat`，或命令行 `npm run backup`）：

```bat
backup.bat                   :: 备份到 D:\CharacterLibrary-Backup\<时间戳>\，保留最近 5 份
npm run backup -- --keep 10  :: 保留 10 份
npm run backup -- --sample 30 :: 抽多少个文件比内容哈希（默认 12，0 = 不比）
```

### 它到底做了什么

1. **先给索引库做快照**（`VACUUM INTO`，服务开着也安全，含 WAL 里已提交的改动），
   然后打开**快照本身**跑 `integrity_check` 并核对行数 —— 校验的是副本，不是源库
2. 把数据盘顶层**所有目录和散落文件**复制到暂存区 `<备份根>\.staging\<时间戳>\`
   （`.catalog` 单独处理，只带 `library.db`；`.covers` 视频封面属于媒体，照常复制）
3. **以快照里的 `media` 记录为准逐条核对**：每条 `rel_path` 必须存在、字节数必须等于库里的
   `bytes`；设过视频封面的连 `poster_rel` 一起核
4. 再按 `--sample` 抽若干文件比 **sha256**（抓「大小一样、内容不同」这种静默损坏）
5. 全部通过才把暂存目录改名成正式的 `20261027-123302\`，写 `MANIFEST.txt` + `RESTORE.md`
6. 最后才清理旧备份，而且**只清「名字对 + 有 MANIFEST + 没有 FAILURE.txt」的目录**

为什么不用「文件数 + 字节数」核对：那既证明不了内容一致，也挡不住
「快照之后新入库的文件不在备份里」——这种备份恢复出来会有打不开的条目。
现在只要有一条记录在备份里找不到对应文件，备份就算失败。

### 失败了会怎样

失败的那一份会改名成 `<时间戳>.failed\`，里面写 `FAILURE.txt`（原因 + 时间），
**不会**被当成可用备份，也**不会**触发旧备份清理。看目录就知道哪次没成：

```
D:\CharacterLibrary-Backup\
  20261026-133946\          正式备份
    MANIFEST.txt            备份时间 / 来源 / 文件数 / 字节数 / 抽样哈希 / 完整性
    RESTORE.md              一步步的恢复说明
    .catalog\library.db     索引快照
    .covers\                视频自定义封面
    角色库\ 人物库\ …       媒体原件
  20261027-123302-3.failed\ 失败的一次（有 FAILURE.txt，不能用来恢复）
```

### 恢复

详见每份备份里的 `RESTORE.md`，要点：

1. **关掉服务**（确认 7788 端口没有监听）
2. **先给现有目录改名留档**，不要直接覆盖
3. 目标目录里如果还有 `library.db-wal` / `library.db-shm`，**先删掉** ——
   旧 WAL 会被当成新库的日志重放，能把刚恢复的库改坏
4. 把备份里的所有内容（含 `.catalog\library.db`、`.covers`）拷回去
5. 启动，核对首页条目数，随便点开几张图和视频确认能打开
6. 确认无误再删第 2 步的留档目录

索引里的路径都是相对 `DATA_DIR` 的，所以换盘符、换目录只改 `config.js` 一行（或环境变量），
数据库不用动：

```bat
set CL_DATA_DIR=D:\CharacterLibrary
set CL_CACHE_DIR=D:\my-cache
start.bat
```

如果数据盘没插上，启动会直接报错停下来，不会偷偷在 C 盘建一个空库。

文件名前缀是内容 sha256 的前 10 位：**同一文件重复上传会自动跳过**，不会占两份。

## 文件操作出问题时会怎样

手动整理素材难免遇到「文件被占用 / 只读 / 权限不足」，这些情况**不会**再被当成成功：

- **删除**：先删磁盘文件，删不掉就返回 409 并**保留记录**（页面还会看到它，可以再来一次），
  错误里带 `EBUSY` / `EPERM` 这类真实原因；批量删除返回 `{ done, failed:[{id, reason}] }`，
  前端提示「已删除 2 个媒体，1 个失败：…」。只读属性会先自动清掉再重试，不算失败。
- **跨角色移动**：文件先搬、再写库；写库失败会把文件**搬回原处**，并在响应里说明。
  搬之前写一条 `<数据目录>\.catalog\pending-moves\*.json`，进程中途被杀，
  下次启动按它收尾（数据库已指向新位置就删记录，没指向就把文件搬回去）。
  搬不回去的会追加到 `.catalog\recovery.log`，人工可以照着处理。
- **目标已有同名文件**：比对**完整 sha256**。真一样才删源去重；不一样就改存 `名字-1.扩展名`，
  两份都留着（以前只凭文件名里的 sha 前 10 位就删源，理论上会误删）。
- **删条目 / 删图包**：目录没删干净会记进 `recovery.log` 并在提示里说明还剩多少文件，
  **不会**自动去删「看起来像残留」的目录。


### 人物库 / 角色库：一个目录一个条目

```bash

```

会算哈希、按月份建包，可重复执行（同 sha256 跳过）。

**`--move` = 搬而不是抄**：`node src/import-cli.js "<源目录>" --name "显示名" --move`。

重复但库里找不到实体的一律保留并在结尾列出。跑完顺手清掉源目录里空掉的子目录，**根目录保留**。
不加 `--move` 时源目录一个文件都不动。

## 性能（本机实测：NVMe SSD + 16 线程 CPU）

| 项目 | 数值 |
|---|---|
| 导入 538 个媒体（512 MB） | 12 秒 |
| 导入 789 个媒体（252 MB） | 6 秒 |
| 缩略图批量生成 | **45.8 张/秒**（997 个 / 21.8 秒） |

| libvips 内部线程 | 2 |

调优依据（24 张真实图为样本）：

| 配置 | 吞吐 |
|---|---|
| 串行 | 19.4 张/秒 |
| 并发 8 + libvips 16 线程 | 59.3 张/秒 |

libvips 内部线程给太多，会和外部并发互相争抢，2 是最优点。

**缩略图在入库时生成**：上传、导入都会顺手生成，所以新内容不用等。

**列表与详情页（v3.30）**

| 项目 | 改法 |
|---|---|
| 进详情页 | 只等 `api.media(id)` 一个请求就出图；图包媒体列表在后台补，回来只更新「x / y」和箭头 |
| 翻页 | 复用内存里的列表，只请求当前这张的详情；相邻图预取（`new Image()`） |

| 上传 | 只刷本次写入的图包封面；条目统计 leading + trailing 合并 |
| 总览 | 1.5s TTL 缓存 + 写请求即失效；嵌入视图复用父级数据，切库只发 1 次请求 |

## 已知限制

- 上传单文件上限 4 GB，单次最多 400 个（压缩包同样适用）
- 解 rar / 7z 需要本机有 7-Zip 或 WinRAR（Windows 自带的 `tar.exe` 也能读）；zip 不需要任何外部工具
- `mkv` / `avi` 浏览器可能无法直接播放
- 媒体在库内移动图包只改数据库，不移动文件（这是有意的，方便随时重分类）
- 暂不支持批量框选移动（API 已有 `PATCH /api/media/:id`）

## 版本控制

仓库：`https://github.com/zhexianqaq/character-library`（private，默认分支 `main`）。
**只提交代码**：媒体原件、`.catalog/library.db`、`.cache/`、`shots/`、`node_modules/` 都在 `.gitignore` 里。

### 约定

- **一次改动 = 一个 commit + 一个 annotated tag**，tag 名就是版本号
- 纯文档改动（只动 README / CHANGELOG）单独提交、**不打 tag** —— tag 只标功能与修复
- 提交信息第一行 `vX.Y: 主题`，正文写「为什么改」和「踩到了什么坑」（这些是以后排查的线索）
- 版本号：加功能 / 改结构用两位（`v3.25`），修 bug 用三位（`v3.24.1`）
- **打 tag 前 e2e 必须全绿**（当前 140 条），并至少对改动页面截一张图确认 `console errors: 0`
- 发布：`git push origin main --follow-tags`（tag 和提交一起推）
- 涉及数据库结构的改动，顺手跑一次 `npm run backup` 留快照

### 常用命令

```bash
git tag -l --sort=creatordate                 # 全部版本，按时间
git tag -n9 v3.24                             # 看某一版的说明
git log --oneline v3.24..v3.25                # 两版之间改了什么
git show v3.25 --stat                         # 某一版动了哪些文件
git log -S "novel_group" --oneline            # 哪个提交引入了某个字段 / 字符串
git tag --contains <commit>                   # 这个提交从哪一版开始有
```

> annotated tag 的 `git rev-parse v3.25` 给的是 **tag 对象**的 SHA，要看提交得写 `v3.25^{commit}`。

### 怎么回退

```bash
git checkout v3.24          # 只看看旧版长什么样（detached HEAD，看完 checkout main 回来）
git revert <commit>         # 撤销某一版的改动，历史保留（推荐）
git reset --hard v3.24      # 本地硬退，之后必须 force push，只在确定不要后面那些提交时用
```

数据库是只加列不删列的（`migrate()` 只 `ADD COLUMN`），所以**回退旧代码不会把库读坏**；
反过来「先用新版跑过、再退回旧版」也是安全的，新增的列旧代码当它不存在。

### 发版检查清单

1. `cd server && npm run e2e` —— 全绿（当前 140/140）
2. 对改动页面跑一次 `node tools/shot.mjs <url> <out.png>`，确认 `console errors: 0`
3. 更新 `CHANGELOG.md`（新版本写最上面）和本文件的功能表 / 版本表
4. `git add -A` → `git commit` → `git tag -a vX.Y -m "..."` → `git push origin main --follow-tags`
5. 结构有变就 `npm run backup`
