# 资料库

自己的本地素材库。**不是扫描器**——素材是复制进库里的，归你管、可分类、可编辑。资料库下可以并排放多个**库**，每个库结构完全一样、互相独立。

素材源（`E:\X-Vault珍藏馆`）只是取料的地方，源文件始终保持不动。

## 快速开始

双击 `start.bat` → 浏览器打开 `http://127.0.0.1:7788`

## 层级

```
资料库（我的资料库）
 ├ 人物库   ← 放真人
 │  └ 人物（名字 / 账号 / 简介 / 标签 / 平台账号）
 │     └ 图包（按月份，也可手动新建）
 │        └ 图片 / 视频
 └ 角色库   ← 放虚拟角色
    └ 角色（名字 / 简介 / 标签 / 出处）
       └ 小库（官图 / cosplay / 同人）
          └ 图包（按月份）
             └ 图片 / 视频
```

两种库结构完全一致，**区别只在条目上那一栏**：

| 库类型 | 那一栏 | 填什么 | 点一下 |
|---|---|---|---|
| 人物库 · 真人 | **平台** | 平台 + ID（主页网址选填） | 有网址就跳转，没有就复制 ID |
| 角色库 · 虚拟 | **出处** | 类型 + 作品名（链接选填） | 有链接就跳转，没有就复制作品名 |

出处类型预设：游戏 / 动画 / 漫画 / 小说 / 电影 / 剧集 / 特摄 / 舞台剧 / 同人 / 原创（也可自己输）。

**小库（只有角色库有）**：每个角色下面分三个小库——`官图` / `cosplay` / `同人`，
每个小库内部再按月分图包。角色页图包区上方是三个切换标签，带各自图包数；
上传和「＋ 图包」都会落到当前选中的小库，磁盘路径是
`角色库/<角色>/<小库>/<图包>/图片|视频`。

新增库：首页库标签右侧的 **＋**，填名字并选类型。新库在磁盘上会建同名目录
（`E:\CharacterLibrary\<库名>\`），建条目、传文件时自动按五层展开。

## 怎么往里加东西

1. 首页右上角 **＋ 新建人物 / 新建角色**（按钮名跟着当前库变），填名字、账号、简介
2. 进详情页，点 **＋ 上传图片 / 视频**，可多选、可拖一堆视频
3. 上传后按文件名里的日期**自动归到对应月份图包**；没有日期的进「未分类」
4. 也可以点 **＋ 图包** 手动建月份包；图包支持重命名 / 删除（删除只是解除归属，不删媒体）

详情页还能编辑简介（点一下就变输入框）、加标签、改封面。

### 标签

条目上可以打标签，点标签行右侧的 **+ 标签** 打开弹窗：上方输入框、下方已有标签列表（点击选中/取消）、底部确认。

- **查重**：输入一个已存在的标签，会直接选中它并提示「已经有 xxx 了」，不会加出第二个
- **相似校验**：和已有标签很像（包含关系、二元组相似度 ≥ 0.5）时先拦一下，提示「和 xxx 很像，避免重复？」，确实要加可以点「仍然添加」
- 标签是全库共用的，跨库、跨条目复用

**媒体自动继承标签**，不用手动打：

```
图片的标签 = 条目的标签 + 条目名本身 + 库标签（人物 / 角色）
```

比如纸悦的一张图，标签是 `cosplay / 写真 / 纸悦 / 人物`。灯箱右上角能看到。

### 右键菜单

界面上几乎每个东西右键都有菜单：

| 右键位置 | 能做什么 |
|---|---|
| 首页 · 条目卡片 | 打开 / 编辑名称 / 添加素材 / 打开本地文件夹 / 删除 |
| 首页 · 空白处 | 新建条目 / 新建库 / 刷新 |
| 角色页 · 图包卡片 | 打开 / 编辑名称 / 编辑标签 / 添加素材 / 打开本地文件夹 / **解散** / **删除** |
| 角色页 · 空白处 | 上传素材 / 新建图包 / 编辑资料 |
| 角色页 · 平台（出处）卡片 | 编辑 / 复制 / 删除 |
| 图片视频瓦片 | 打开 / 重命名 / 编辑标签 / 打开本地文件夹 / 移动到其他图包 / 删除 |
| 图包页 · 空白处 | 上传素材（进这个包）/ 编辑图包 / 编辑标签 / 打开本地文件夹 |

**解散 vs 删除**（图包）：

- **解散**：只删图包这个壳，里面的媒体变成「未归包」，文件一个都不动
- **删除**：图包连同里面的媒体、磁盘文件一起删掉，不可恢复（会二次确认）

**重命名图片**只改库里的显示名，磁盘文件名保持不动——磁盘名前面那段是内容 sha256，去重靠它。

### 平台账号栏（人物库）/ 出处栏（角色库）

详情页 hero 区中间那栏，内容跟着库类型变：

| | 人物库（真人） | 角色库（虚拟） |
|---|---|---|
| 栏目标题 | 平台 | 出处 |
| 上排 | 平台（下拉可选可输）+ ID | 出处类型 + 作品名 |
| 下排 | 主页网址（选填） | 作品链接（选填） |
| 点卡片 | 有网址跳转，否则复制 ID | 有链接跳转，否则复制作品名 |

共同行为：

- **＋** 添加，悬停卡片出现 ✎ 编辑 / ✕ 删除
- **超过 4 条不再把整栏拉高**：容器内无滚动条滚动，底部渐隐阴影提示还有内容，滚到底阴影自动消失
- 第一列固定 50px，**第二列左边缘严格对齐**，超长省略 + 悬停显示全名

链接只接受 http/https，写 `x.com/xxx` 会自动补成 `https://x.com/xxx`（前后端各补一次）。

  角色库\                             ← ① 角色库（shelves，可以有很多个）

D:\ams\workbuddy\character-library\
  start.bat
  test.bat
  .cache\                             ← 缓存盘（SSD，随项目走）
    thumbs\                           420px WebP，瀑布流用
    preview\                          1400px WebP，灯箱用

## 备份

整个库就是一个目录，**备份 = 复制 `E:\CharacterLibrary`**。`.cache` 不用备份——删了会自动重建。

一键备份（双击 `backup.bat`，或命令行 `npm run backup`）：

```bat
backup.bat                  :: 备份到 D:\CharacterLibrary-Backup\<时间戳>\，保留最近 5 份
npm run backup -- --keep 10 :: 保留 10 份
```

它会做三件事：

1. 用 SQLite 的 `VACUUM INTO` 给索引库做**一致快照**（服务开着也能拿到完整副本，含 WAL 里未落盘的改动）
2. 把每个库的媒体原件整体复制到 D 盘（跨盘，不受单盘故障影响）
3. 核对文件数与字节数，**对不上直接报错退出**，不写 MANIFEST

```
D:\CharacterLibrary-Backup\
  20261026-133946\
    MANIFEST.txt          备份时间 / 来源 / 文件数 / 字节数 / 完整性
    .catalog\library.db  索引快照
    角色库\   人物库\
```

恢复：把某份备份里的**所有内容（含 `.catalog`）**拷回 `E:\CharacterLibrary` 覆盖即可。
索引里的路径都是相对 `DATA_DIR` 的，所以换盘符、换目录只改 `config.js` 一行，数据库不用动。

也可以用环境变量覆盖，不动代码：

```bat
set CL_DATA_DIR=E:\CharacterLibrary
set CL_CACHE_DIR=D:\my-cache
start.bat
```

如果数据盘没插上，启动会直接报错停下来，不会偷偷在 C 盘建一个空库。

文件名前缀是内容 sha256 的前 10 位：**同一文件重复上传会自动跳过**，不会占两份。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/overview` | 资料库 + 角色库列表 + 总量 |
| POST | `/api/shelves` | 新建角色库 |
| GET | `/api/shelves/:id/characters` | 角色列表（`q` / `sort`） |
| POST | `/api/characters` | 新建角色 |
| GET / PATCH / DELETE | `/api/characters/:id` | 详情 / 改资料 / 删除 |
| GET / POST | `/api/characters/:id/packs` | 图包列表 / 新建 |
| POST | `/api/characters/:id/media` | 上传（multipart `files`，可带 `packId`） |
| GET | `/api/characters/:id/media` | 角色全部媒体 |
| GET / PATCH / DELETE | `/api/packs/:id` | 图包详情 / 改名封面 / 删除 |
| GET | `/api/packs/:id/media` | 图包内媒体 |
| PATCH / DELETE | `/api/media/:id` | 移动图包 / 删除 |
| GET | `/t/:id` `/pv/:id` `/m/:id` | 缩略图 / 预览图 / 原文件（Range） |

> 媒体接口用 `/t` `/pv` `/m`，页面路由用 `/` `/s/:id` `/c/:id` `/p/:id`，两套前缀不能重名。

## 从外部目录批量导入

```bash
cd server
node src/import-cli.js "E:\X-Vault珍藏馆\<角色目录>" --name "显示名"
```

会复制、算哈希、按月份建包，可重复执行（同 sha256 跳过）。

## 性能（本机实测：NVMe SSD + 16 线程 CPU）

| 项目 | 数值 |
|---|---|
| 导入 538 个媒体（512 MB） | 12 秒 |
| 导入 789 个媒体（252 MB） | 6 秒 |
| 缩略图批量生成 | **45.8 张/秒**（997 个 / 21.8 秒） |
| 缩略图缓存命中 | **14ms** |
| 队列并发 | 默认 8，可用 `THUMB_CONCURRENCY` 调 |
| libvips 内部线程 | 2 |

调优依据（24 张真实图为样本）：

| 配置 | 吞吐 |
|---|---|
| 串行 | 19.4 张/秒 |
| 并发 8 + libvips 16 线程 | 59.3 张/秒 |
| **并发 8 + libvips 2 线程** | **66.3 张/秒** |

libvips 内部线程给太多，会和外部并发互相争抢，2 是最优点。

**缩略图在入库时生成**：上传、导入都会顺手生成，所以新内容不用等。
存量数据用 `POST /api/warm` 一次性补齐。当前库 1334/1334 = 100% 就绪，打开任何图包都是缓存命中。

## 怎么测试

### 一行命令跑自动化

```bash
cd server
npm run e2e
```

会启动一个无头 Chrome，真实点按钮、真上传文件、真删数据，最后打印 `20/20 通过`。
跑的是这些（顺序执行，测完自动清理测试角色）：

| 场景 | 断言 |
|---|---|
| 首页 | 角色卡片渲染、样式表生效 |
| 角色详情 | 进入 `/c/:id`、图包按月渲染 |
| 全部媒体 | 瀑布流 tile 数、缩略图真的加载出像素 |
| 灯箱 | 点击打开、大图加载、Esc 关闭 |
| 新建角色 | 弹窗 → 填表 → 提交 → 跳转 → 名字正确 |
| 上传 | 内存生成 PNG（文件名带 20250315）→ 自动建出「2025 年 3 月」图包 → 统计刷新 |
| 删除 | 接口删除 → 再查返回 404 |

传文件用的是 `DataTransfer` + 内存 `File`，不依赖本机任何图片，所以换机器也能跑。

### 只看界面长什么样

```bash
cd server
npm run shot -- "http://127.0.0.1:7788/c/1" "../shots/char.png" 1440 1100 4000
```

参数：`<url> <输出路径> [宽] [高] [等待毫秒]`。等待给够时间让图片加载，否则会拍出一片灰块。
脚本同时会把页面的 JS 报错打出来——`console errors: 0` 才算干净。

### 手动测试清单（改完前端先过一遍）

1. **改了前端看不到变化** → `Ctrl + Shift + R` 强刷。后端已设 `no-cache`，正常刷新就够，但强刷能排除一切缓存干扰。
2. **首页**：角色卡片有封面、数量徽章对得上。
3. **角色页**：点简介能变输入框、失焦自动保存；点标签能删；「＋ 上传」选几张图，进度条走完后图包数增加。
4. **图包页**：瀑布流保持原图比例；视频有播放角标；点开能播、能拖进度条。
5. **删图包**：媒体变成未归包而不是消失（回角色页「全部媒体」里还在）。
6. **删角色**：`library/<角色>/` 目录会一起删掉，**这个不可恢复**。

## 已知限制

- 上传单文件上限 4 GB，单次最多 400 个
- `mkv` / `avi` 浏览器可能无法直接播放
- 媒体在库内移动图包只改数据库，不移动文件（这是有意的，方便随时重分类）
- 暂不支持批量框选移动（API 已有 `PATCH /api/media/:id`）
