# Character Library

[English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [繁體中文](README.zh-TW.md) · **Русский** · [Français](README.fr.md) · [简体中文](README.md)

> Локальная галерея аниме- и косплей-материалов, которая работает только на вашем компьютере.
> Изображения и видео разложены по четырём уровням — **библиотека → запись → пакет → изображения | видео** —
> и структура папок на диске полностью повторяет то, что видно в интерфейсе. Мозаичная сетка, теги,
> читалка комиксов, автоматическая распаковка архивов и инкрементальная синхронизация с диском уже внутри.
> **Данные не покидают компьютер: ни облака, ни загрузки, ни телеметрии.**

**Это не сканер.** Материалы **копируются** в библиотеку, их можно распределять и редактировать;
исходная папка остаётся нетронутой.

> Интерфейс и комментарии в коде — **только на упрощённом китайском** (локализации в приложении нет).
> **Это сокращённая версия.** Подробное руководство (все экраны, таблица API, настройки производительности,
> известные проблемы и история версий) есть только в двух файлах: **[简体中文](README.md)** и
> **[English](README.en.md)**.

## Что умеет

- **Пять типов библиотек** — персоны (косплеер + аккаунты), персонажи (по произведениям), ресурсы
  (одна карточка на произведение), эмодзи / разрозненные картинки (плоская), новеллы (встроенная читалка
  TXT + иллюстрации + мешки комиксов). Плюс «общая библиотека» — склад неразобранных файлов.
- **Четыре способа добавить материалы**
  - Перетаскивание: до 400 файлов за раз, до 4 ГБ на файл, с прогрессом и причиной ошибки для каждого
  - **Перетащите архив**: zip / rar / 7z / tar.gz распаковывается автоматически, берутся только изображения
    и видео. zip разбирается собственной реализацией (китайские имена в GBK не ломаются),
    **для зашифрованных архивов приложение спрашивает пароль и запоминает его**
  - Массовый импорт из папки: дедупликация по sha256, пакеты по дате из имени файла, `--move` удаляет
    источник только после проверки копии в библиотеке
  - **Перетаскивание в десктопную оболочку**: браузер получает только байты, оболочка — реальный путь,
    поэтому **исходный файл можно удалить сразу после успешного импорта**
- **Просмотр** — мозаичная сетка рисуется порциями (десятки тысяч плиток без тормозов), четыре варианта
  сортировки, широкие изображения занимают две колонки, миниатюры создаются при импорте
- **Теги** — имя пакета вида «персонаж-костюм» автоматически делится на два тега, имя записи тоже
  становится тегом, клик по тегу открывает страницу тега
- **Поиск** — верхняя строка ищет по списку библиотек, записям, библиотеке ресурсов и странице ресурса;
  сервер учитывает и теги: по названию произведения находятся записи, у которых оно есть только в теге
- **Читалка комиксов** — прокрутка / одна страница / разворот, направление справа налево, по высоте или
  по ширине, полный экран, перелистывание колесом, боковая панель сжимается в узком окне
- **Пакетные операции и клавиатура** — Shift для диапазона, Ctrl для добавления и снятия, `Ctrl+A` —
  выделить всё, Delete, Esc; контекстное меню почти на каждом элементе
- **Синхронизация с диском** — каждое переименование, перемещение и удаление пишет запись в журнал
  **в той же транзакции**, что и изменение данных. Кнопка синхронизации обрабатывает только эти записи,
  не сканируя всю библиотеку, и никогда не удаляет файлы, которые положил не он
- **Резервные копии** — `VACUUM INTO`, выборочная проверка хешей и MANIFEST, хранятся 5 последних копий

## Технологии

| Часть | |
|---|---|
| Фронтенд | Чистые ES-модули, **без сборки** (никаких webpack / vite / бандлеров), CSS-переменные и компоненты, написанные вручную |
| Бэкенд | Node 22 · Express 5 · better-sqlite3 · sharp (libvips) · ffmpeg |
| Оболочка | Rust · tao + wry (WebView2) — **один exe на 689 КБ**, статический CRT, никаких DLL |
| Хранение | Индекс SQLite + оригиналы на диске; пути хранятся **относительно** корня данных, поэтому библиотеку можно перенести на другой диск |

## Быстрый старт

Нужен **Node.js 20+** (разработка и тесты — на 22). База создаётся при первом запуске.

```bash
cd server && npm install && cd ..
start.bat          # запускает сервер и открывает http://127.0.0.1:7788
```

Каталог данных по умолчанию — `E:\CharacterLibrary`. Изменить можно переменными окружения:

```bat
set CL_DATA_DIR=D:\MyLibrary
set CL_CACHE_DIR=D:\my-cache
start.bat
```

Если хочется не браузер, а окно — соберите десктопную оболочку (нужны Rust и VS2022 Build Tools):

```bash
node desktop/build.mjs      # создаёт 资料库.exe в корне проекта
```

exe должен лежать в корне проекта — он ищет `server/src/index.js` вверх по дереву.
Для рабочего стола создайте ярлык.

## Где лежат данные

| Что | По умолчанию | Содержимое |
|---|---|---|
| Программа | папка репозитория | код, `web/`, `server/`, exe, `.cache` (миниатюры, можно удалять) |
| Данные | `E:\CharacterLibrary` (`CL_DATA_DIR`) | оригиналы медиа + индекс `.catalog\library.db` |
| Резервные копии | `E:\CharacterLibrary-Backup` (`CL_BACKUP_DIR`) | папка с отметкой времени на каждый запуск, хранятся 5 |

Данные лучше держать на жёстком диске (объём, последовательное чтение), кэш — на SSD (много случайного чтения).

## Известные ограничения

- До 4 ГБ на файл и до 400 файлов за раз (архивы тоже)
- Для rar / 7z нужен 7-Zip или WinRAR (подойдёт и встроенный в Windows `tar.exe`); для zip ничего не нужно
- `mkv` / `avi` могут не воспроизводиться в браузере
- Перемещение материалов между пакетами внутри одной записи меняет только базу — файлы переедут при
  следующей синхронизации
- Десктопная оболочка только для Windows (WebView2); само веб-приложение работает везде, где есть Node
- **Интерфейс только на китайском.** Слоя i18n нет и не планируется.
